- 금융/세금, 주거, 근로·취업, 건강·생활민원, 정부지원, 자동차를 **콘텐츠 묶음**으로 재분류한다. 기존 /car/ 및 /support/ 슬러그·canonical은 무단 변경하지 않는다.
- 우선 /topics/ 내부에 주제별 앵커/분류 목록을 만들어 실제 기사를 연결한다. 충분한 고유 글과 내용이 생긴 묶음만 별도 색인 허브로 승격한다.
- 첫 화면은 간단한 제목·검색·대표 주제·가장 유용한 최근 확인 글 순서. 이미 있는 메인 아카이브를 또 복제하거나 과도한 광고/장식으로 길게 늘리지 않는다.
- 공개 기사 52개가 홈 링크 그래프에 있지만 **출처 목록형 링크가 존재한다는 사실과 쉽게 발견·이해한다는 것**은 다르다. 클릭되는 주제명과 URL 일치, 사용자가 예상하는 결과를 수동 검수한다.

### 3-2. 금융·세금 (/finance/)
- 기존 6개 금융 기능(금리비교·공시·예적금 이자·대출상환·주담대 계산·금융 허브) 유지.
- 새 글의 목표는 ‘금리표가 길게 나열됨’이 아니라 **실제 선택 조건**: 기본금리 대 최고금리, 우대조건 충족 비용, 세후수령액, 예금/적금 차이, 6·12·24개월 비교.
- 실시간 금융상품 리스트는 공급자 업데이트 시각·우대 조건 원문·데이터 수집 실패 여부를 분명히 표시. 자동 수집 수치를 ‘오늘 실시간 최신’으로 단정 금지.
- 금리·대출 YMYL 콘텐츠는 금융감독원/한국은행/국세청 등 원문과 가정값을 구분. 개인별 대출 가능 여부를 계산 결과로 단정 금지.
- 동적 데이터만으로 검색 유입을 기대하지 말고 **금융상품 비교를 읽는 법과 계산 결과 해석**의 독자적인 가이드를 만든다.

### 3-3. 주거·부동산
- 기존 주거급여·전입/확정일자/임대차 신고·월세공제·주담대 계산기를 연계하여 ‘계약 전→계약/전입→거주 중→퇴거/보증금 반환’ 여정으로 보여준다.
- 분양정보 샘플 세 건은 현재 미승인 가상 데이터다. 실제 현장으로 표기하거나 색인시키지 않는다. 광고주 증빙·공식 공고·이미지 권리·상태 종료 규칙이 생기기 전 기능 확장하지 않는다.
- 보증금·퇴직금·지원제도 관련 법률/세금 기사는 법률 자문처럼 확답하지 않고 공인 절차와 예외를 공식 자료로 설명한다.

### 3-4. 정부지원·근로·일상민원
- 현재 36개 support 글을 최소 ‘복지·가족’, ‘취업·노동’, ‘세금·환급’, ‘주거’, ‘건강·보험행정’, ‘증명·민원’의 편집 태그로 먼저 재분류한다.
- 제도 공고의 신청 중/마감/상시/예정 상태를 콘텐츠 목록에도 표시할 수 있게 검토. 상태 최신성을 공식 출처로 확인하지 않으면 임의 표시 금지.
- 연도가 바뀌었다는 이유로 같은 글을 복제하지 않는다. 기존 canonical에서 공고/금액/사례를 업데이트하거나 실제 정책이 달라 독립 검색 의도가 생길 때만 별도 신규 글을 낸다.
- 기존 2026 정책 글은 2027 적용 시 상태·금액·귀속연도를 재검토하고, 그전까지 2027 숫자를 추정해서 넣지 않는다.

### 3-5. 먹거리 (/food/)
- 12개월 선택기·36개 기본 레시피·장보기 기능은 유지한다. 브라우저 수동 상태저장, 상품 검색 링크 등 기존 동작 훼손 금지.
- 14개 상세 식품 글이 특정 계절에 치우쳐 있으므로 ‘12월~3월 제철·보관·위생’ 묶음부터 새 원문형 글을 보강한다.
- 조리 안전은 식약처/질병관리청/농촌진흥청 등 공식 근거를 사용하고, 익힘온도·시간·보관일을 모든 식품에 일괄 적용하지 않는다.
- 사진 출처(Pexels 등)는 HTTP 403 봇 차단과 실제 저작권/원문 삭제를 구분한다. 재사용 라이선스 및 이미지 출처를 별도 검증한다.
- ‘먹거리’와 ‘핫딜’을 연결하는 제휴 링크는 공식 정보/광고 구분과 noindex 정책을 유지한다.

### 3-6. 오늘 (/today/)·검색 (/search/)
- 오늘 페이지는 속보 콘텐츠가 아니라 동적 데이터 대시보드다. 마지막 데이터 시각·출처·실패시 대체 공식 링크가 사용자에게 실제로 보이는지 검수한다.
- 날씨/뉴스/환율/코인/주식 각각 로딩/정상/부분실패/전부실패 화면을 테스트한다. 저장소의 캐시 정책을 존중하고 검증 없이 ‘실시간’ 단어를 붙이지 않는다.
- 검색은 79개 실제 색인 대상 목록을 탐색한다. 한국어 붙여쓰기/띄어쓰기·자주 묻는 말과 같은 뜻 검색어에서 정확도가 떨어지는지 실제 질의 목록으로 검수한다. 0건일 때는 관련 주제 카드 제공을 고려한다.
- 검색 결과 페이지 자체는 noindex 유지. 검색어별 대량 색인 페이지를 만들지 않는다.

### 3-7. 행사 (/events/)·분양정보 (/real-estate/)
- 행사: 현재 API 키 없음 → 0건. API 자격증명·공식 API 이용권한 확보 후 실제 7~30일 내 행사 10건 이상을 출처/날짜/장소/상세 링크와 함께 수집하고 중복·종료행사 제외 검증. 데이터 없으면 메뉴 비노출/noindex 유지.
- 분양: 실제 승인 데이터 0건. 가상 3개는 시안 상태 유지. 실제 정보가 준비되면 승인·철회·종료·이미지 권리·공식 모집공고 검수 과정을 먼저 설계한다. ‘분양중’ 같은 내부 sample 필드는 공개 사실로 사용하지 않는다.

### 3-8. 광고·수익화
- AdSense: 소유권 확인과 광고 실제 송출은 별개. **승인 여부를 코드 유무로 추정하지 않는다.**
- 쿠팡 전역 배너와 텐핑/AdSense가 함께 있는 페이지에서 첫 화면 정보 대 광고 비중, 광고 로딩으로 인한 CLS, 본문·공식기관 CTA 구분을 실제 모바일 캡처로 기록한다.
- ADPICK은 할인 전 가격을 보장하지 않아 ‘핫딜’이 아님(README에 명시). 콘텐츠·메뉴·광고 고지를 일치시켜 불필요한 클릭/오해 감소.
- 수익을 늘리기 위한 광고 증설보다 콘텐츠 유입·다음 글 이동률·사용자 과업 완료를 먼저 확인한다.

## 6. 실제 검색·성과 측정 명세

**기술적 SEO 성공 = 구글 검색 순위 상승이 아니다.** 검색엔진별 실제 데이터를 확보하기 전에는 ‘상위 노출’, ‘색인 완료’, ‘애드센스 승인 가능’이라고 선언하지 않는다.

1. GSC에 canonical https://pagero.kr/life/에 관한 유효한 속성 범위를 확인(도메인 속성 또는 정확한 URL 접두어).
2. 최근 28일과 직전 28일의 노출/클릭/CTR/평균순위, 상위 50개 질의·URL을 기록. 성과 없는 신생 사이트는 절대값과 증가율을 혼동하지 않는다.
3. 색인된 페이지/미색인 사유/리다이렉트 처리·중복 canonical·크롤링 오류를 각각 보고, 83개의 사이트맵이 즉시 83개 실제 색인된다고 가정하지 않는다.
4. Naver 서치어드바이저에서 수집·노출/웹마스터 진단과 301 구 도메인 이동 상태를 비교한다. 과거 life.pagero.kr 검색 결과 잔존은 관찰되지만 현재 전환 실패를 뜻하지 않는다.
5. 콘텐츠 기획은 (노출 많은데 CTR 낮음) → 제목/설명 개선, (11~30위) → 본문 사례/내부링크 보강, (유입 없음/주제 공백) → 고품질 신규 글 검토의 순서로 결정한다.
6. 전환/비즈니스 지표는 검색 방문·글→다음글 클릭·공식사이트 아웃바운드·계산기 사용·제휴 클릭을 **개인정보 최소화**로 정의. 광고클릭 부정 유도 금지.
7. 재검증 기간: 배포 당일은 기술적 장애, 7~14일은 검색 수집 상태, 28일 이상은 노출·CTR·방문 변화 추적에 사용. 색인·트래픽 예측치는 쓰지 않는다.

## 7. 운영·기술부채와 기존 지침 충돌

- **정식 주소:** https://pagero.kr/life/ . README 상단과 HANDOFF_PAGE_SEO_OPERATIONS_KO.md의 https://life.pagero.kr 표기는 구 운영명이므로 문서에서 현행 canonical로 정정하고 301 이력만 남긴다.
- **게시물 URL:** 각 가이드의 /car/slug/ 또는 /support/slug/ 정식 URL 하나가 3개 파트 본문 전체를 갖는 색인 대상. /2/와 /3/은 분리 열람을 위한 noindex 보조 화면. HANDOFF 문서의 ‘첫 URL에는 첫 번째 파트만 표시’ 설명은 현 운영 검증 내용과 다르다. 이 문서와 LIFE_INTEGRATION_RELEASE_GATES.md를 현재 기준으로 통합할 것.
- **성장분야 수:** automation/growth-taxonomy.json은 현재 **21개**. README의 ‘20개’는 업데이트 필요. 21개는 편집 주제 후보 분류이지 공개 카테고리/콘텐츠 개수 아님.
- **원고 큐:** 발행된 slug가 topic-queue.json에서 pending_deployment에 남아 있는 사례를 점검. 큐 상태는 실제 게시글 JSON, 빌드 검색목록, 사이트맵과 동기화할 것.
- **빌드 구조:** build-production.mjs에서 83개의 node 단계(및 기타 npm 단계)를 순차 실행. 편집·광고·CSS·SEO HTML 후처리가 여러 파일에 흩어져 있다. 즉시 전면 재작성 말고 ‘기능별 담당 스크립트/중복 변환/선후관계’ 목록을 먼저 만들고 회귀 테스트와 함께 단계적으로 통합.
- **Cloudflare 비용:** 메인 inlet 프록시가 /life/ 정적자산 요청도 Functions로 처리하므로 원본 Pages가 정적 제외했다고 총 Functions 비용이 0이 되는 것은 아니다. 실제 비용 수치는 Cloudflare Analytics로만 확인.
- **실시간 API:** 건강·금융·기상·이벤트 출처의 실패를 빈값/재시도/오래된 캐시와 구분. API 키와 개인정보/민감 정보는 브라우저 HTML·공개 JSON·GitHub 파일에 노출 금지.
- **콘텐츠 유지:** 이전 고품질 글, 사용자 도구, 제휴 표시, 광고설정, main Pages 프록시·도메인 등은 새 UI/글 작업을 이유로 임의 삭제하지 않는다. CSS를 덧씌우며 전역 디자인을 무너뜨리는 임시 수정 금지.

## 10. 결론 및 이번 감사의 종료 기준

현재 가장 큰 부족점은 **링크검사나 자동차 기사 수가 아니라 ‘여러 서비스가 있는 사이트인데 이용자가 찾는 분야의 원본 정보가 적고 분류가 혼재한 것’**이다. 금융·주거·세금·근로·생활민원·통신·의료·식품의 고유 자료를 확보하고, 실제 분야별 경로로 연결하는 것이 우선이다. 행사 0건과 가상 분양 3건을 공개 콘텐츠 규모에 포함해서는 안 된다.

이 감사 문서 작성 이후에도 **수동 비주얼 QA, GSC 색인/유입 실측, 미확인 외부링크의 개별 접근 가능성**은 열린 항목이다. 99/103 회귀 통과를 이 항목들의 완료 증거로 해석하지 않는다. 이후 코딩·발행은 위 표 A→B를 원칙으로 하고, 작업 지시 없이 ‘SEO 링크패치’를 무한 반복하지 않는다.
