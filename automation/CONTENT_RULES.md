# 생활비서 자동 발행 규칙

## 목표
현재 실제로 신청·사용·접수 중인 자동차 행정과 정부지원 제도를 우선 발행한다. 포털 이용법, 공고문 읽는 법처럼 정책명이 없는 일반론보다 **정책 실명·신청기간·대상·금액·현재 상태가 분명한 콘텐츠**를 먼저 선택한다.

하나의 주제는 3개 연속 페이지로 구성한다. 페이지 수만 늘리는 빈 화면은 만들지 않고 각 페이지마다 다른 질문을 해결한다. 화면에는 `1단계`, `2/3`, 진행률 표시를 노출하지 않는다.

## 콘텐츠 선정 우선순위
1. 현재 신청·접수·사용 기간에 들어온 전국 단위 정책
2. 검색 수요가 큰 자동차 세금·검사·이전등록·보조금
3. 마감일 또는 예산 소진 가능성이 있는 제도
4. 다음 분기에 신청이 시작되는 제도
5. 상시 제도와 계산·조회형 생활행정

`정부지원사업 찾는 법`, `지원자격 읽는 법`, `서류 준비 일반론`처럼 제도명이 없는 글은 새로 발행하지 않는다. 기존 글도 실제 정책 콘텐츠로 교체한다.

## 한 콘텐츠의 고정 구조
- 첫 페이지: 누가 대상인지, 현재 신청기간과 핵심 조건
- 두 번째 페이지: 금액·조회·계산·예외·실제 신청 순서
- 세 번째 페이지: 준비서류·완료 확인·후속조치·공식 사이트 이동

URL:
- `/<category>/<slug>/`
- `/<category>/<slug>/2/`
- `/<category>/<slug>/3/`

첫 번째와 두 번째 페이지에는 다음 내용 버튼을 중심으로 둔다. 공식 신청·조회 사이트 버튼은 마지막 페이지에만 제공한다.

## 품질 기준
- `series.parts`: 정확히 3개
- 각 페이지 본문: 1,000자 이상
- 세 페이지 전체 본문: 3,000자 이상
- 각 페이지 제목·설명·핵심요약 3개 이상
- 각 페이지에 내용과 직접 관련된 이미지 1개와 구체적인 대체텍스트
- FAQ 2개 이상
- 공식 출처의 실제 원문 URL과 자료 확인일
- 검색·완성 글의 자료 기준 영역에서 공식 출처를 클릭해 원문을 확인할 수 있어야 함
- 금액·기간·대상은 발행 당일 공식 페이지 또는 공고 원문으로 확인
- 기간이 바뀌지 않는 설명은 법령·공공기관 상시안내를 활용 가능
- 같은 문장과 핵심 내용을 세 페이지에 반복하지 않음
- 글 목록에는 해당 콘텐츠의 대표 이미지를 표시

## 애드센스 콘텐츠 가치 우선 검증 (2026-10-21 적용)

아래 기준은 기존의 '3페이지·3,000자' 구조보다 우선하는 편집 품질 판단 기준입니다. **글자 수, 발행 수, 키워드 수, AI 생성 속도를 콘텐츠 품질의 증거로 간주하지 않습니다.**

1. **근거의 깊이:** 정책·법률·혜택 관련 신규 글은 서로 구별되는 공식 원문 상세 URL 2개 이상을 확인합니다. 기관 메인화면과 포털 검색 결과만 연결한 글은 발행하지 않습니다. 제출 시각과 실제 내용 확인 시각을 기록하고, 수치·날짜마다 어떤 출처인지 분명히 합니다.
2. **사용자의 구체적 결정을 지원:** 독자가 확인할 수 있는 조건별 선택표, 공식 공고의 수치 해석, 위험한 예외, 단계별 판단 기준 중 해당 주제에 실질적으로 도움이 되는 내용을 반드시 넣습니다. 임의 숫자를 쓰면 가상 예시라고 명확히 표시하고 실제 보조금·수수료로 오해시키지 않습니다.
3. **중복 검색의도 차단:** 같은 검색 질문을 제목만 바꾸어 대량으로 발행하지 않습니다. 이미 동일한 답이 있으면 기존 글에 정정·추가하고, 동일한 문단을 3개 연속 페이지에 반복하지 않습니다.
4. **직접 경험을 꾸미지 않음:** 방문·신청·전문가 인터뷰·실측을 실제로 하지 않았다면 했다고 쓰지 않습니다. 작성자·전문가 경력도 확인된 사실만 표시합니다. 스톡 이미지로 실제 경험을 증명하는 것처럼 꾸미지 않습니다.
5. **시점과 상태 구분:** 접수 중·마감·차기 공고 대기는 서로 구분합니다. 공식 근거가 갱신되지 않았다면 발행·정정일만 최신으로 바꾸지 않습니다. 정책별 자격은 관할기관의 심사 결과가 우선이라는 범위를 유지합니다.
6. **검증 후 게시:** `node scripts/editorial-quality-audit.mjs`의 위험 신호를 확인하고 `npm run check`, `npm run build`까지 통과해야 합니다. 자동 검사는 독창성이나 사실의 정확성, 애드센스 통과를 보증하지 않습니다.
7. **기존 글 우선 보강:** 전수 감사에서 직접 출처가 없거나 사례·비교가 부실한 글은 새 글보다 먼저 수정합니다. 링크만 붙여 놓고 사람이 이해하기 어려운 기사는 통과시키지 않습니다.

신규 게시물은 `scripts/validate-content.mjs`에서 직접 공식 상세 출처 2개, 출처 확인일, 사례·비교·계산 중 최소 1개를 자동 검사합니다. 이 요건의 충족은 최소 요건일 뿐, 실제 원문 대조와 의미 있는 독창적 분석을 대신하지 않습니다.

## 발행 순서
1. `automation/topic-queue.json`에서 현재성·검색수요가 높은 주제를 선택한다.
2. 기존 글과 제목·검색의도·슬러그 중복을 확인한다.
3. 정부 부처·공공기관·지자체 공식 자료를 웹에서 확인한다.
4. 신청기간·금액·대상·예산소진 여부는 최신 공고를 우선한다.
5. 세 페이지를 각각 독립적인 정보량으로 작성한다.
6. 이미지 사용 가능 여부와 대체텍스트를 확인한다.
7. `npm run check`와 `npm run build`를 통과한 경우에만 커밋한다.
8. 큐와 발행 로그를 같은 변경에서 갱신한다.

## 금지
- 보험·보험금·보험 비교·보험 가입 권유 콘텐츠
- 정부기관으로 오인시키는 이름·로고·표현
- 지급·선정·환급 결과 보장
- 광고 클릭 유도
- 내용 없이 이동 버튼만 있는 페이지
- 화면에 1단계·2단계·3단계 또는 1/3 진행률 노출
- 지역명·연도만 바꾼 대량 문서
- 확인하지 않은 금액·기간·대상
- 오래된 공고를 현재 정책처럼 게시
- 정책명이 없는 일반론 중심 콘텐츠

## 광고 배치
광고는 본문과 명확히 분리한다. 다음 내용 버튼과 공식 사이트 버튼 바로 위·아래에는 붙이지 않고, 광고를 버튼·조회결과·공식 링크처럼 보이게 만들지 않는다.
